<h2>v0.0.0-beta.27 — Animation and PlayerModel fixes</h2>

<h3>Fix</h3>
<ul>
<li><strong><code>setupAnim</code> restored before pose copy</strong>: <code>model.setupAnim(renderState)</code> is now called before <code>copyPoseFromPlayer</code>. This was removed in beta.25, leaving the armor model frozen in default T-pose with no animation. Base vanilla animation is now applied first, then the PlayerModel pose (including modifications from Player Animation Core or any animation mod) is copied for rotation and scale.</li>
<li><strong><code>getPlayerModel()</code> refactored</strong>: now uses <code>Minecraft.getInstance().player</code> and <code>EntityRenderDispatcher.getRenderer()</code> with an explicit <code>instanceof AvatarRenderer</code> check, instead of the fragile <code>(RenderLayer) this.getParentModel()</code> cast that could fail depending on the caller context in the renderer hierarchy.</li>
</ul>
