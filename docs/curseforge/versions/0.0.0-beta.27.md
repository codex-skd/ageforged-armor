<h2>v0.0.0-beta.27 — Animation fixes + robust PlayerModel access</h2>

<h3>Fix</h3>
<ul>
<li><strong>Armor stuck in T-pose (regression from beta.25)</strong>: <code>model.setupAnim(renderState)</code> was removed in beta.25, leaving the armor model in default T-pose with no animation. Restored in beta.26 — now base vanilla animation is applied first, then the PlayerModel pose (including Player Animation Core modifications) is copied for rotation/scale.</li>
<li><strong>Helmet positioned wrong / face exposed</strong>: <code>copyPart</code> was copying <code>x/y/z</code> from the PlayerModel to the armor model, but both have different default positions (e.g. player head at <code>y=0</code>, armor head at <code>y=1</code>). Now only copies rotation and scale, keeping the armor model&#8217;s original position offsets.</li>
<li><strong>PlayerModel access refactored</strong>: <code>getPlayerModel()</code> now uses <code>Minecraft.getInstance().player</code> and <code>EntityRenderDispatcher.getRenderer()</code> with an explicit <code>instanceof AvatarRenderer</code> check, instead of the fragile <code>(RenderLayer) this.getParentModel()</code> cast that could fail depending on the renderer hierarchy at call time.</li>
</ul>

<h3>Technical Changes</h3>
<ul>
<li><code>MixinHumanoidArmorLayer.getPlayerModel()</code> — removed <code>RenderLayer.getParentModel()</code> cast in favor of a direct lookup via the entity render dispatcher.</li>
<li><code>MixinHumanoidArmorLayer.copyPoseFromPlayer()</code> — copies rotation and scale only, preserving the armor model&#8217;s default x/y/z offsets.</li>
</ul>
