<h2>v1.1.2 - Fix broken loot-only setup on NeoForge 26.2.0.32-beta</h2>

<h3>Fix</h3>
<ul>
<li><strong>41 crafting recipes failed to load</strong>: NeoForge 26.2.0.32-beta changed the <code>Ingredient</code> codec — it no longer accepts the legacy <code>{"item": "id"}</code> object format, only a plain item id string (or an array, or a <code>#tag</code>). Since these armors are loot-only by design, the 44 recipe JSONs were removed instead of reformatted, along with their 41 now-orphaned "recipe unlocked" advancements.</li>
<li><strong>Global loot modifier registry failed with "No key type"</strong>: this NeoForge version no longer reads a <code>global_loot_modifiers.json</code> entries list — it scans every file under <code>data/*/loot_modifiers/*.json</code> directly as an individually-typed modifier. The obsolete listing file was removed.</li>
<li><strong>9 of 19 armor loot drops were silently missing in-game</strong>: the datagen run was misconfigured (<code>clientData()</code> instead of <code>serverData()</code>), so it never actually regenerated the loot modifier files after the drop tables were expanded in code. Fixed the run config and regenerated all 17 loot modifier files to match the current drop table.</li>
</ul>
